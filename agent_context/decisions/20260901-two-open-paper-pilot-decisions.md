# Two open decisions the paper pilot cannot make for itself

DATE_UTC: 2026-09-01
RAISED_BY: Claude Code, `20260901-1030Z-claude-seven-item-sweep.md`
STATUS: OPEN — both need the founder, and neither is a defect to be fixed quietly
DEADLINE: **session 11, the first rebalance, approximately 2026-09-14.** Decision 2 fires there.
  Decision 1 can fire any morning.

Both came out of round six's repairs. In each case the defect half is fixed and shipped; what is
left changes **what the pilot does**, not what it observes, and that is not a change to make
unilaterally during a live run.

---

## Decision 1 — concurrent sessions: prevent the overlap, or keep only preventing the loss?

### What is already true

Two sessions ran concurrently and the second to finish silently discarded the first's entire trading
day: 16 fills, `sessions_completed` 10 to 11, one session's fees, with both reports on disk and no
error anywhere (R6-17).

`save_portfolio` now takes an optional prior hash and refuses to overwrite a file that changed since
the session loaded. **There is still no lock.** Two sessions can overlap; what is prevented is the
silent *loss*. The second to finish is refused and says so, and both sets of artifacts survive.

### What is not decided

What should the loser do? The options are not equivalent:

| Option | Behaviour | Cost |
|---|---|---|
| **A. Leave as is** | Second session raises at the final write, after trading all day | A full day of simulated decisions is computed and then discarded. The operator finds out at 15:30 |
| **B. Advisory lock at startup** | Second session refuses at 09:00 and exits immediately | Needs a stale-lock policy. A crashed session leaves a lock file, and the next morning refuses to trade — a fail-closed that costs a day |
| **C. Lock with a liveness check** | Second session refuses only while the first is genuinely alive (PID plus start time) | Most correct, most code. `logs/paper_runs/runner.pid` already exists and is already written |

**My recommendation is C**, because `runner.pid` is already maintained and the failure mode of B --
a crash on Monday silencing Tuesday -- is worse than the problem being solved. But the stale-lock
policy is a judgement about what should happen on a morning nobody is watching, and that is yours.

## Decision 2 — does the pilot re-weight at rebalance, as the measured strategy does?

### What is already true

The entry loop acts only when `current_held == 0`, so a name already held is never topped up or
trimmed. Weights drift and **the drift is permanent**. Worse, a book that still contains the
selection submits no orders, so `evaluate_order` — the only enforcement point for
`max_position_weight` — never runs. A book 90% in one name against a declared 30% limit passes every
check the session makes (R6-08).

`weight_drift_report` now reports this at every rebalance. **It reports; it does not correct.**

### Why this is a decision and not a bug fix

The measured strategy re-equal-weights at every rebalance. The runner does not. That is the
"the system that executed was not the system that was validated" failure this repository has
already been burned by once, and it argues for fixing it.

Against that:

- Correcting it changes **what the pilot trades**, days before its first rebalance. The first ten
  sessions would have been generated by one rule and the eleventh onward by another, in a record
  whose whole purpose is to be a clean observation.
- The obvious partial fix is worse than nothing. Making `rebalance_executed` require weight
  conformance would mark the rebalance as not executed, so the hold clock never resets, so it
  retries every session — and the entry loop still cannot fix weights, so it fails forever. That is
  a livelock, not a repair.

### The three real options

| Option | What it means |
|---|---|
| **A. Implement re-weighting** before session 11, and restart the pilot's record from session 1 | Honest, expensive: ten sessions of observation discarded |
| **B. Implement re-weighting** at session 11 and record the rule change in the session log | Keeps the record, at the cost of a discontinuity in the middle of it |
| **C. Leave the runner as it is**, and state in every report that this pilot observes a buy-and-hold-the-selection variant, **not** the measured strategy | Cheapest and most honest about what the artifact is, and it means the pilot is not evidence for the strategy that was actually screened |

**My recommendation is A if this pilot is meant to be evidence about the strategy, and C if it is
meant to be a test of the plumbing.** It cannot be both, and the current state is C without having
said so anywhere.

Ten sessions is a small sunk cost against 101 governed trials that found no edge. The thing worth
protecting is not the ten sessions; it is the ability to say honestly what the pilot measured.
